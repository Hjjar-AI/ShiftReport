# Android-led web functional map

**Android is the main client and behavior reference**, confirmed by the owner on3November2026. The local Windows/Linux Flask/Jinja client retains Python3.8.10 and browser-appropriate file/navigation controls. This is a source inventory, not proof of complete runtime or cross-client parity. [Setup](../../web/README.md) · [Behavior/evidence](../status/current-state.md#local-flask-client) · [Remaining checks](../status/testing-handoff.md#local-flask-client).

Android references below are relative to `android/app/src/main/java/com/hos/rushdpatients/`. Existing working web services remain independent under `web/shiftreport/`; the archived desktop is no longer the parity baseline.

Owner-confirmed exclusions remain **biometric unlock, text/mixed report delivery and legacy Excel/VBA import/export**. Current-format CSV synchronization remains; Android can perform the one-time legacy import. Historical receipt formats stay readable. Settings search is now selected and implemented under this Android-led request.

The web UI keeps its accepted muted design. Shared wire/backup/database versions, encryption/key protection, clinical rows and native clients are unchanged. The iPhone host still owns its explicit route allowlist; new web-only guide/priority/manual-move navigation is hidden there pending its separate adaptation. Source coverage and focused offline checks do not establish browser accessibility/geometry, Windows execution, PDF renderer equivalence or live Android↔web acceptance; these belong solely to the handoff.
