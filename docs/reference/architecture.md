# Architecture

[Implementation/limits](../status/current-state.md) · [Protocol](telegram-protocol.md) · [Roadmap](../status/roadmap.md)

## Accepted synchronization scope

Manually retrieved/published complete Telegram snapshots and reviewed reports; last successful pinned write wins. No automatic sync/remote merge/atomic multi-writer guarantee/required backend. Clinical patient/shift saves are last-save-wins; retained revision columns support bookkeeping, not stale-edit rejection. Review/authority protect publication and privileged registry mutations, not competing remote writes. Timestamps record known events, not freshness. Android manual Fetch stages registry and current patient bundle from one observed index, then replaces both with cursors/baselines and one local Undo in a Room transaction. Pending local edits are replaced without merging; Undo restores both locally, without publication. Current/previous pointers follow successful index-write order, not upload-message-ID order. Doctor-only Fetch validates retained current assignments; full Fetch resolves paired registry/patient changes. Patient publication retains clinical/registry/delivery guards. A single explicit review may include pending doctor bytes and patients; admin publishes doctors first. Unreviewed later edits remain pending.

## Ownership and local commits

Publication and Fetch require the current single-ward CSV bundle; old multi-list/plain-CSV Telegram containers are unsupported. No dated-list picker/copy or previous-publication local-view workflow. Keep device-local Fetch Undo and reviewed admin rollback of the prior remote publication. Existing stored clinical rows are preserved.

Android selects its current section through an existing-settings ID, independent of the stored shift date. Fetch, restore and Empty Start select their result; Undo restores the previous selection. Date lookup is permitted only when no explicit incoming ward ID was supplied; an explicit ID never aliases another ward of the same date. Stored legacy rows remain; multi-section product support is a [separate design](../decisions/multiple-sections.md).

08:30 only labels the work day: no automatic new ward/rollover or date-based edit/publish/send gate. Existing ward identities/rows continue across days; captured report dates remain immutable after review.

Screens own presentation/navigation; ViewModels own state/mutations and delegate. Repositories atomically commit clinical changes; `KnownShiftSnapshot`/`PatientPublicationStatus` derive current-ward pending/count/briefing from the same normalized content/order, excluding retired tracking/task metadata; historical wards remain stored without blocking current fetch, and a missing baseline alone does not make an empty roster-free ward pending; new audit recording and clinical-history UI/loads are disabled, with old records retained; patient/doctor sync share singleton store/mutex. Extraction must not duplicate sessions/reviews/artifacts/drafts/locks; desktop facades preserve imports and defer optional cyclic imports. Blocking work off-main; cancellation separate.

Unknown or newer pinned state fails closed rather than becoming an empty state. Immutable doctor wire decodes are cached by file ID, while live actor/authority checks remain fresh. Reviewed publication leaves later local edits pending and never self-downloads or creates a Fetch Undo. Snapshot lineage remains bookkeeping/history, and patient revisions also drive saved-card reveal.

Privacy/PIN removes clinical composition but retains signed-in navigation/ViewModels and `SaveableStateHolder`: stable ActivityResult keys require the holder, not just controller. Sign-out discards both; credentials never saveable.

## Access and project boundaries

Protected-file join; manual configuration at creation. Pre-login reconnect validates before replacing credentials, preserves clinical/key/topics and blocks cross-project changes. Sign-out retains enrollment; local PIN supports offline return, first enrollment/shared privileges retain identity checks. BotFather revokes; token holders can bypass client gates.

Android pin override binds reviewed pin/config/live first-admin authority and rechecks before seeding; import only newly seeded reference. No old-data import/history deletion/automatic device transfer/initialized-local replacement; pin checks non-atomic. Desktop requires private challenge/live group admin/empty pin+workspace, with encrypted UNKNOWN before writes. Raw desktop settings stay private. Optional authenticated encryption protects keys, while PDF/metadata stays readable; missing device keys preserve files. Admin checks below UI. [Setup](../guides/telegram-setup.md).

## Clinical and presentation boundaries

Hidden assignment day is business metadata for assignment-PDF highlighting: stamp local creation/actual supervisor changes at Save, preserve on unrelated edits/fetch/restore, compare to captured report day. Nullable date persists in approved DB6/optional CSV7 column; no editor control or author stamp. Publication equality includes it; ordinary report delivery identity excludes it and freezes legacy receipt serialization.

Plain checklist tasks; legacy owner/deadline/priority fields remain compatible wire/storage only. No new completion/editor identity or time stamps; old fields remain readable. Teams independent of patient cover; CSV retains omitted active doctors. Backup/restore never publishes; transactional live responsible-doctor role checks protect Save/recycle/replacement. Restore advances revisions; rejection rolls back clinical/pending state.

Shared fields/tokens standardize presentation; callers own drafts/validation/busy/selection/review. Report review exposes each selected artifact directly and derives opened counts/next preview/send gating from one readiness projection; its fixed primary action advances through Next/Preview/Upload-send, with secondary navigation below. Resident/supervisor pickers always use full-width stacked rows with natural wrapped-value height, preserving the user's font size. RTL/growing48dp/adaptive layouts, clinical-first edit/demographic-first create, labs and fixed keyboard-safe actions. Appearance exposes four accents/text size/reduced motion; spacing follows shared defaults, A4/A5 only. Appearance/accent/severity remain independent; PDF headings follow the light app accent; saved text unchanged. Brief individual/immediate bulk or reduced motion. Stable visible IDs define rounds; buttons supplement gestures. [UI guide](../guides/android/ui.md).

Desktop follows the simplified clinical workflow: three reviewed transfer actions, plain clinical text, four accent families. The patient list stays central, with direct roster/tasks/summary navigation, compact hospital/account header and secondary connection/data tools. Desktop cards start compact/collapsed, with individual and immediate bulk expansion retaining full clinical/task content. Bulk mode clears per-patient overrides; expansion/pinning never change saved clinical/export order. Edit/Full file/Pin/Delete remain visible. Normal/comfortable spacing lives in Sorting-first View Options. Neutral light/dark/AMOLED surfaces and outlined fields match the shared accents. A separate startup intro uses the original emblem on white and shared About credits; its three-second monotonic deadline is skippable, never extended by a hold. Asset decoding runs on a worker; clinical connection starts after dismissal. Search has an explicit label and a separate row on narrow windows. CTk wrapping converts measured pixels back to logical widths before applying widget scaling; long button labels wrap without shrinking fonts. Collapsed disclosures reset their requested height; hidden grid actions use grid_forget so scaling cannot restore them. Grouped tasks save completion against the current patient and offer a two-second local Undo, with no attribution/time stamp. The report footer retains one full-width primary and secondary actions below after scaling. Report review owns a captured08:30 day across render/confirmation/transport; it never replaces stored snapshot dates/IDs. Daily idle recycle retention works through the existing IO executor, with a grace week for undated entries and no OS service. Retired task-time/audit computation is removed while old encrypted metadata stays compatible. Desktop UI fonts share a Tajawal family token; existing bundled Regular/Bold faces are registered for the process/application off-main before Tk, without system installation. Appearance rebuilds preserve the font family, shaped editors retain logical Unicode/caret mappings, and OS-owned dialogs may keep their system font. Details uses the existing RTL section control and task/badge helpers; its owner retains section/scroll positions, captured rounds IDs and guarded Edit. Presentation state never enters clinical persistence.

### Dated lab groups

Patient lab groups have stable IDs, optional title/date and multiline results, in explicit user order. Android Room initial schema1 stores `labGroupsJson`; ungrouped lab text remains readable as one untitled/undated group. Desktop encrypted snapshot JSON retains the same data. CSV8 appends the structured groups and keeps `labs` as a human-readable projection; current readers validate dates/IDs and reject mismatched projection rather than dropping clinical text. Encrypted backups share the CSV codec; drafts include blank/unfinished groups and dates. Search/cards/text/classic reports use the readable projection; reviewed artifacts include group structure. Android/desktop A5 cards place lab panels in the fixed clinical columns, with wrapped/tinted headings, continuation titles and keep-together where space permits. No inferred lab grouping or clinical interpretation for saved patient data; explicit sample-generator panel headings define only the fictional demo groups.

### Snapshot identity and initial database schema

Ward and doctor IDs are identity; dates/names are labels. Android initial schema1 uses non-unique ward-date and doctor-name indexes. The owner reset the schema baseline before any older projects were initialized; historical schema migrations are removed, and future migrations start from1. Active roster names and Telegram identities remain validated; Telegram ID uniqueness remains enforced by SQLite. One registry transaction soft-deletes omitted rows, releases changed account bindings, stages incoming rows, applies the patient snapshot and validates the final pair. Failed validation rolls everything back. Date-only local lookup prefers the selected ward, with deterministic fallback; explicit remote IDs never use date lookup. No new ward-browsing feature or wire format is introduced. Desktop stores its workspace by IDs in an encrypted body.

## Reviewed PDF and delivery identity

Android review captures CSV/text content and exact opened PDF/options/SHA-256; subsequent local edits remain pending, rather than invalidating approved content. Live actor/authority/assignment/destination checks remain; missing/changed PDF file requires preview. Publish before delivery, including subsets. UNKNOWN before report network writes blocks shift/destination retry until authorized resolution or a one-use permit for the same exact artifact. The uncertain receipt remains evidence after extra-copy permission. A pending copy permit restricts that route to the approved content/format key. Consuming it durably restores the original UNKNOWN until the copy is acknowledged; failure/interruption leaves the original actionable. Received/not-received resolution is available in delivery history before using the permit and revokes it. In-flight copy/original records cannot be resolved concurrently. Local receipts cannot prove non-delivery or cross-device exactly-once.

Android delivery identity uses only the current explicit field list; historical receipt fingerprints and aliases are removed. A reviewed report keeps its captured label date for text/PDF day counts. Definite Telegram rejections before any delivered chunk are NOT_SENT; partial delivery stays uncertain. Receipts are not automatically pruned: removing UNKNOWN loses unresolved evidence, while removing SENT can permit duplicates. Supervisor receipt message IDs remain separate from General-chat sent pointers.

Real/demo drawer actions use one exhaustive `WardNavigation.openDrawerAction`; destination callbacks choose live or memory adapters. `AssignmentsExportWorkspace` is shared just like Ward/Report/Doctors workspaces. `PdfAssignmentRenderer` owns the common layout without session/storage/transport dependencies; production `PdfAssignmentExporter` checks current admin identity around rendering, while demo uses only its dummy snapshot and every-page DEMO label. Shared presentation changes propagate to demo automatically; new action/data contracts still need explicit memory behavior.

A5 cards preserve full clinical pagination and full-page links/headers; native renderer text metrics/pagination can differ (below). Assignment sheets retain applicable current-roster notices. Standalone clinical Export is draft-only and copies separately opened every-page-labelled files. Android exposes it only on Preview, with one primary Preview→Save action and a collapsed report chooser. Normal copies are an explicit, initially checked choice in the main final-confirmed upload/send flow, performed only after all selected reports have confirmed Telegram delivery and copying their exact previews; no implicit General local save. Desktop general/batch review captures the same optional choice. Local-save failure keeps delivery confirmed, reports a local-only problem and never creates a send retry. Draft mode never publishes or authorizes Telegram delivery. Supervisor/unassigned drafts remain. Admin names-only assignments have a separate side-navigation Preview→Save route, outside both report pages and all publication/delivery gates, with no draft marking or roster requirement. Local admin/data/identity and exact opened bytes remain checked; desktop uses authenticated cached admin authority for this local operation only. Ordinary send retains active roster/authority/exact destination checks.

These checks govern application Save/Share actions. PDF previews remain readable in external viewers, which can offer their own Save/Share; this is workflow guidance and client enforcement, not document copy protection or remote atomicity.

### A5 card geometry

Android source defaults: 420×595pt; side/top/bottom margins 4/12/8mm, body/section/title-navigation spacing 5/4/2pt, body/heading/name fonts 12.5/13/16pt. Demographics/admission/team and badges span the page; diagnosis→treatment→follow-up→labs→tasks flow down the right clinical column, then left, then next page (8pt gutter, no backfill/nested columns/layout switch). Panels keep continuation headings, separate inset 0.5pt rules and 3pt gaps. The card-index opening places its15pt bold title/date in opposite right/left header columns, measuring header height before the content frame. Totals use13pt bold with psychiatric label/count in parentheses; separate resident/supervisor roster lines use11.5pt with2pt gaps. Only populated middle-column index cells have a light theme tint; outer cells remain white. The classic opening uses the same date/totals text in one measured band below the roster, without a fixed minimum title height; final summary remains totals-only. The three-column RTL index fills down then left, with 28pt cells/names up to 15pt; patient navigation uses 12pt text and whole-page destinations preserve headers. Retain roster/context/page/creation/DEMO footers. Android/desktop assignments use A5 with three team tables per row. [Current defaults/limits](../status/current-state.md#reports-and-exports) distinguish renderers; matching fixtures are required for parity claims.

## Isolation and platform choices

The independent local browser client in `web/` uses a Flask application factory/Jinja and exact Python3.8.10 dependencies with a loopback Waitress launcher. Jinja keeps the local setup Python-only. Headless current-format protocol/crypto/store/PDF services are adapted into `web/shiftreport/core/`, without importing native GUI code or changing `old/desktop/`. Browser-owned state/guards live in `workspace.py`; route modules own clinical, provisioning, data and report controllers. Real-project bodies are encrypted in SQLite, while demo clinical state remains memory-only. Per-project request locks and a new per-data-directory process lock are intended to serialize local state ownership; this does not make Telegram atomic across clients. A project has one recoverable form owner; review-specific extra-copy permits are consumed durably before transport. Stable rounds and presentation-only grouping/pinning are session-owned. Render-scoped Arabic shaping caches avoid retaining clinical text after generation. [Setup/source ownership](../../web/README.md), [functional map](web-capabilities.md) and [verification](../status/testing-handoff.md#local-flask-client) distinguish source coverage from actual acceptance.

Shared Ward/Report/Doctors workspaces depend on controller state/actions; production adapters forward to existing Hilt ViewModels, while demo adapters use one memory-only repository/fake snapshot and receipts. Shared drawer/appearance/forms/cards/readiness/text/PDF prevent separate demo UI drift. Explicit simulation notices and every-page DEMO PDFs; no production store/session/transport or entered identity/PIN retention. Reset/exit discards clinical state; only isolated accent/appearance persist. Samples/action adapters remain maintenance points. [Demo](../guides/android/demo.md).

Desktop fingerprint-bound AES-GCM before SQLite, DPAPI/Linux-passphrase keys and platform path/lock/PDF adapters. Logical Arabic input/caret/clipboard/Save separate from shaping; unfinished drafts/cached enrollment/shared authority distinct. [Operations](../../old/desktop/README.md).

Design basis: Android adaptive/Compose accessibility, I-PASS,NHS warnings,WCAG2.2; rationale, not verification. Voice/templates remain deferred in Roadmap; unselected UI stays in [decisions](../decisions/android-ui-options.md).

Startup renders the intro as `StorageAccessGate` loading content while encrypted access runs on IO. Only successful access constructs repository-backed content; failure remains explicit and never resets stored data. A remembered movable intro is reused under the saved theme after readiness, retaining entrance state and the original monotonic deadline. Tap skip cannot bypass the gate; if storage is still pending the intro remains until access resolves.

### Permanent-admin handover

`PermanentAdminTransfer` constructs a role-only proposal; `DoctorSyncCoordinator` owns Android prepare/publication and live actor/project/registry checks. Reviews are ephemeral and consumed on attempt. Transfer requires an unchanged synced local registry, publishes a complete snapshot using the existing shared state mutex, verifies its file/pointer and only then applies local roles/base/cursor together. Uncertainty leaves local roles unchanged and requires Fetch; a fresh attempt checks published permanent authority, preventing blind repetition after a successful remote handover. Telegram remains last-successful-write-wins across clients. Normal publication cannot change permanent-owner IDs. Manual Fetch accepts the currently published portable permissions; imports and local edits retain their protected-target checks. A stale client can accept the final published ownership snapshot without reconstructing missed intermediate handovers. Desktop uses existing administration review/fingerprint/receipt/readback handling with its opaque project ID bound to transfer reviews. No schema, wire, clinical timestamp or Telegram-group ownership change.
