# Local Flask functional map

Independent local Windows/Linux Flask/Jinja client on **Python 3.8.10**. This maps the current native desktop entry points to browser functions; it describes source coverage, not acceptance of every platform or live transport. [Setup](../../web/README.md) · [Behavior/evidence](../status/current-state.md#local-flask-client) · [Remaining checks](../status/testing-handoff.md#local-flask-client).

| Native function / reference owner | Browser entry and implementation |
|---|---|
| Local launch, project tools, diagnostics (`desktop_gui.py`, `desktop_shell_layout.py`) | `web/run.py`/`run.sh`/`run.cmd`: loopback Waitress, independent environment, per-data-directory lock; `/diagnostics` shows runtime/dependency versions without connection secrets. |
| Protected join, creation, reconnect, token replacement (`desktop_onboarding.py`, `desktop_project.py`, `desktop_tokens.py`) | `/connection`, `/connection/review`, `/project/create`, `/project/creation`; protected `.srjoin.json` only, mandatory recovery connection download before final creation, project/key/topic validation, live-admin replacement guards. |
| Private identity, enrolled PIN, lock (`desktop_access.py`) | `/identity`; Telegram code and local encrypted enrollment/throttling, explicit lock, server idle expiry and browser activity/cross-tab handling. Local PIN grants no Telegram session. |
| Continuous ward, clinical forms (`desktop_patient_actions.py`, `desktop_patient_draft.py`, `desktop_clinical.py`) | `/`, `/patients/new`, `/patients/<id>/edit`; Add demographics first, Edit clinical fields first, tasks/labs/badges and assignments, explicit Save, stable visible Save-next, last-save-wins with current existence/assignment/ward guards. |
| Recovery, delete/recycle | One encrypted project form owner; opening recovery transfers ownership and rejects old-window autosaves. Invalid/unfinished/final submitted input is retained, Cancel preserves recovery, Save and draft deletion commit together. Explicit discard; `/recycle` retains weekly recovery. |
| Filters, stored sort, grouping/cards (`desktop_patient_filters.py`, `desktop_sort.py`, `desktop_cards.py`) | Ward search normalizes Arabic; supervisor, mine, pending tasks, priority/badges/unassigned/urgent/today filters. `/ward/options` stores manual/name/admission/supervisor/workbook/custom levels. Ward View Options owns grouping, spacing, card actions/pinning; presentation pinning never reorders exports. |
| Details, rounds, task board, dashboard (`desktop_details.py`, `desktop_workflow.py`, `desktop_dashboard.py`) | `/patients/<id>` has section links/text copy/captured-round navigation; `/tasks` filters by responsible supervisor/resident and status, checks captured ward on completion/Undo; `/dashboard` shows totals and links to clinical filters. No new task ownership/deadline/completion metadata controls. |
| Roster (`desktop_patient_actions.py`) | `/ward/roster` and the first section of `/reports`: active doctor selection without a cap, including an actionable empty roster. |
| Registry/teams/permissions (`desktop_admin_ui.py`, `desktop_doctors.py`, `desktop_teams.py`) | `/doctors`, `/doctors/manage`: reviewed CRUD/roles/account/destination/rank/permanent-admin transfer, CSV import, batch resident memberships. Unlinked residents remain visible; membership review does not change patient assignments. Custom titles remain storage-only. |
| CSV/backup/local recovery (`desktop_csv.py`, `desktop_backup.py`, `desktop_data_actions.py`) | `/data`: current patient/doctor CSV, protected `.rpb`, encrypted `.srdraft` export/review/restore. Clinical restore preserves local enrollment, connection and durable delivery receipts. Demo permits dummy PDF export only. |
| Fetch/Undo/publication/rollback (`desktop_data_actions.py`, `desktop_publication.py`, `desktop_empty_start.py`) | `/data` Fetch/doctor Fetch/local Undo; `/sync` reviewed complete current-ward publication, admin previous-publication rollback and collapsed advanced empty start/destination administration. No dated ward browsing or atomic multi-writer claim. |
| Reports and local exports (`desktop_report_actions.py`, `desktop_export_review.py`, `desktop_pdf*.py`) | `/reports`: doctor/target selection, captured day, A5 cards/table/paragraphs or text, local DRAFT or reviewed combined publish/send; explicit local supervisor splitting includes an unassigned subset. `/export/assignments` is independent local admin names-only export with no roster mutation. |
| Exact preview/Save/Share/optional copies | `/reports/review/...` retains rendered bytes. Open before Save/Share, invalidate changed content/registry/accent, no rerender. Share uses browser file sharing when available or downloads the same file for sharing from the device. Normal local copies are optional and require all selected deliveries to confirm. |
| Receipts, uncertainty and extra copies (`desktop_workspace_receipts.py`, `desktop_report_review.py`) | Durable UNKNOWN before transport, receipt resolution in `/sync`, exact-original artifact upload by hash, explicit extra-copy review. A durable permit belongs to that displayed review and is consumed once with its UNKNOWN receipt before transport; replay cannot mint another permission. Original UNKNOWN remains unresolved. |
| Appearance, report defaults/time, About/intro (`desktop_appearance.py`, `desktop_pdf_settings.py`, `desktop_intro.py`) | Isolated live/demo accent/appearance; muted light/dark/AMOLED, text through130%, reduced motion, compact expandable account/hospital header and grouped secondary navigation. `/settings` owns timezone/default format/layout. Three-second intro retains its deadline during holds/reload; About retains credits/emblem. |

Native source is unchanged. Headless current-format services are independent copies in `web/shiftreport/core/`; browser state belongs to `workspace.py`, controllers to the route modules, presentation to Jinja/static assets. Task metadata, encryption/key protection, current wire/backup formats and clinical rows remain intact. Arabic shaping caches are bounded to rendering and cleared afterward; the immutable ligature pattern is cached without changing reshaper output or native geometry.

The inventory covers existing desktop functions and the agreed presentation/state follow-up. Operating-system UI is represented by browser-appropriate equivalents; browser file sharing has a download fallback. Windows execution, live cross-client Telegram acceptance and full renderer parity are not inferred from source coverage. The verification handoff is the sole remaining-check list.
