# دليل إعداد تليجرام في ShiftReport

هذا الدليل لمن ينشئ المشروع لأول مرة. **إذا كنت تنضم إلى مشروع موجود، يكفي ملف `.srjoin.json` من المدير وعبارة مروره؛ لا تحتاج إلى جمع الرموز أو معرّفات المواضيع بنفسك.** اختر الملف وأدخل عبارة مروره بأي ترتيب، ثم اضغط «فتح ملف الانضمام ومراجعة المشروع». بعد فتحه تُمسح العبارة من الحقل؛ راجع المشروع ثم اضغط «التحقق والانضمام».

## ابدأ بأبسط إعداد

في شاشة إنشاء أندرويد: **1. ربط المجموعة الإدارية → 2. تعريف المدير الأول → 3. اختيار حماية البيانات**. مجموعة واحدة تكفي؛ اترك حقول المواضيع ووجهة المقيمين فارغة للبدء.

**المجموعة الإدارية** لملفات CSV المرضى وسجل الأطباء والفهرس المثبّت؛ مواضيع البيانات داخلها اختيارية. **مجموعة المقيمين** لتقارير PDF، ويمكن أن تكون المجموعة الإدارية نفسها أو مجموعة أخرى. الموضوع قسم داخل المجموعة نفسها وليس مجموعة ثانية. عند ترك مجموعة المقيمين فارغة تُستخدم وجهة PDF الافتراضية في المجموعة الإدارية. إخفاء الحقول الاختيارية يحتفظ بقيم أدخلتها؛ امسحها إذا أردت العودة إلى الوجهة الافتراضية.

في إعدادات أندرويد، **وجهات تقارير المشرفين اختيارية**. لكل مشرف:

| الحقول المدخلة | وجهة تقرير المشرف |
|---|---|
| مجموعة فقط | المحادثة الرئيسية في مجموعة المشرف |
| مجموعة وموضوع | الموضوع المحدد داخل تلك المجموعة |
| موضوع فقط | الموضوع داخل مجموعة المقيمين؛ المجموعة الإدارية عند عدم تخصيص مجموعة للمقيمين |
| الحقلان فارغان | لا إرسال لتقرير المشرف |

موضوع المشرف مستقل عن موضوع PDF العام للمقيمين. لا يتطلب إعداد وجهة نشر أي تقرير؛ الإرسال يبقى بعد المعاينة والتأكيد. دعم مواضيع المشرفين مضاف إلى مصدر أندرويد فقط، ولم يُبنَ أو يُتحقق منه على الهاتف بعد؛ الويب والكمبيوتر خارج نطاق هذا التعديل ولا يدعمان سجل المشرفين ذي المواضيع.

## ما الذي يمكن تغييره بعد إنشاء مشروع أندرويد؟

| الإعداد | التعديل بعد الإنشاء |
|---|---|
| مجموعة المقيمين وموضوع PDF فيها | للمدير من إعدادات الوجهات؛ صدّر ملف انضمام محمياً جديداً وأعد الاتصال به على الأجهزة الأخرى |
| مجموعة وموضوع كل مشرف | للمدير من الوجهات؛ احفظ ثم راجع وانشر سجل الأطباء لتوزيع التعديل |
| رمز البوت | استبدال رمز البوت نفسه بعد تحقق الصلاحية والاتصال؛ ليس تغيير هوية البوت. أعد توزيع ملف انضمام محمي |
| حسابات الأطباء وبياناتهم وفرقهم وصلاحياتهم | من إدارة الأطباء وبحسب الصلاحيات؛ هوية المدير الدائم تتغير عبر نقل الإدارة الدائمة |
| المجموعة الإدارية ومواضيع CSV وسجل الأطباء وموضوع PDF الافتراضي فيها | لا تعديل في مشروع مهيأ؛ إعادة الاتصال ترفض استبدالها. يمكن توجيه PDF إلى المجموعة الإدارية نفسها عبر إعداد مجموعة المقيمين |
| اختيار التشفير ومفتاح البيانات وهوية البوت | ثابتة؛ إعادة الاتصال تحافظ عليها |
| اسم المشفى/المشروع | لا يوجد محرر اسم بعد الإنشاء حالياً |

تغيير مجموعة المقيمين يغيّر أيضاً وجهة المشرف الذي أدخلت له موضوعاً فقط؛ أعد معاينة التقارير بعد التغيير. تغيير مواضيع البيانات أو المجموعة الإدارية ليس جزءاً من هذه الإضافة.

للمعرّفات الرقمية راجع الخطوة 3 أدناه. مساعدة شاشة الإنشاء توضح أيضاً أمثلة روابط رسائل خاصة وفق [بنية روابط تليجرام](https://core.telegram.org/api/links#message-links)؛ رابط الدعوة أو اسم المجموعة ليس معرّفاً رقمياً.

## ما الذي يحدث؟

يستخدم التطبيق البوت للوصول إلى مجموعة المشروع، وحفظ ملفات المزامنة وإرسال التقارير. تبقى قاعدة البيانات المحلية نسخة العمل على جهازك؛ تنزيل البيانات وإرسالها إلى تليجرام عمليتان منفصلتان.

| القيمة | معناها | متى تحتاجها؟ |
|---|---|---|
| رمز البوت `Bot Token` | سر يسمح للتطبيق بالعمل باسم البوت | عند إنشاء المشروع، أو استبدال الرمز كمدير |
| معرّف المجموعة `Chat ID` | رقم يحدد مجموعة المشروع | عند إنشاء المشروع؛ يكون سالباً |
| معرّف المستخدم `User ID` | رقم حساب الطبيب، وليس رقم هاتفه أو اسمه | لتحديد المدير الأول وربط الأطباء بحساباتهم |
| معرّف الموضوع `Topic ID` | رقم قسم داخل المجموعة | اختياري، لتنظيم التقارير والبيانات |
| مفتاح تشفير المشروع | مفتاح مستقل يولّده التطبيق عند اختيار التشفير | ينتقل تلقائياً داخل ملف الانضمام المحمي |

**اسم المجموعة، رابط الدعوة، واسم المستخدم `@name` ليست بديلاً عن المعرّفات الرقمية في حقول التطبيق.**

## ١. إنشاء البوت والحصول على الرمز

افتح [BotFather الموثّق](https://t.me/BotFather) ← `/newbot` ← اختر الاسم واسم المستخدم ← احفظ رمز API كاملاً مع `:` بسرية. ليس `@username`؛ لا تنشره في مجموعة/صورة/Git. إلغاؤه عبر BotFather. [الشرح الرسمي](https://core.telegram.org/bots/tutorial#obtain-your-bot-token).

## ٢. تجهيز مجموعة المشروع

أضف البوت مديراً لمجموعة خاصة مع إرسال الملفات والتثبيت؛ فعّل Topics وأنشئ الأقسام إن احتجتها. أندرويد يسمح بمجموعة ذات تثبيت بعد تأكيد مربوط بالتثبيت والإعدادات وصلاحية المدير الأول الحية؛ يعيد التحقق قبل النشر. التغيير يستدعي مراجعة جديدة. لا حذف للتاريخ أو استيراد بيانات المشروع القديم أو انتقال تلقائي للأجهزة؛ وزّع ملف انضمام جديداً. لا يستبدل الإنشاء مشروع الجهاز المهيّأ. عميل الكمبيوتر يرفض التثبيت الموجود.

البوت المدير يستقبل رسائل المجموعة دون تعطيل Privacy Mode. [خصوصية البوت](https://core.telegram.org/bots/features#privacy-mode).

## ٣. جمع المعرّفات عبر البوت الخاص بك

هذه الطريقة لا تحتاج إلى إضافة بوت خارجي إلى مجموعة المرضى. نفّذها أثناء الإعداد، مع إغلاق التطبيق على الأجهزة الأخرى وإيقاف أي برنامج آخر يقرأ تحديثات البوت.

1. من حساب المدير الأول، أرسل رسالة تجريبية غير طبية إلى البوت في محادثة خاصة.
2. أرسل رسالة تجريبية إلى مجموعة المشروع.
3. أرسل رسالة داخل كل موضوع تريد استعماله.
4. على حاسوب فيه Python 3، شغّل المثال التالي. سيطلب الرمز دون إظهاره، ثم يطبع المعرّفات فقط. **لا تضع الرمز داخل نص الأمر.**

```bash
python3 - <<'PY'
import getpass
import json
import urllib.request

bot_token = getpass.getpass('Bot token (hidden): ').strip()

def api(method):
    request = urllib.request.Request(
        'https://api.telegram.org/bot' + bot_token + '/' + method,
        data=b'',
        method='POST',
    )
    with urllib.request.urlopen(request, timeout=20) as response:
        payload = json.load(response)
    if not payload.get('ok'):
        raise RuntimeError('Telegram request failed')
    return payload['result']

try:
    print('Bot ID (NOT your personal ID):', api('getMe')['id'])
    updates = api('getUpdates')
    if not updates:
        print('No updates: send fresh setup messages and try again.')
    for update in updates:
        message = update.get('message')
        if not message:
            continue
        print('---')
        print('Chat type:', message.get('chat', {}).get('type'))
        print('Chat ID:', message.get('chat', {}).get('id'))
        sender = message.get('from', {})
        print('Sender user ID:', sender.get('id'))
        print('Sender is bot:', sender.get('is_bot', False))
        print('Topic ID:', message.get('message_thread_id', '(absent)'))
except Exception:
    print('Could not read IDs. Check token, network, and webhook/polling settings.')
PY
```

اقرأ النتيجة هكذا:

- `Chat type: supergroup` مع `Chat ID` سالب: معرّف مجموعة المشروع.
- `Sender user ID` لرسالة أرسلتها أنت شخصياً: معرّف حسابك. استخدم رسالة المحادثة الخاصة لتجنب هوية المدير المجهول أو الإرسال باسم قناة.
- `Topic ID` لرسالة داخل موضوع محدد: رقم ذلك الموضوع.
- `Bot ID` يخص البوت؛ **لا تضعه في حقل معرّف المدير الأول**.

`getUpdates` يعرض التحديثات المتاحة للبوت؛ قد لا يعيد رسائل قرأها برنامج آخر. لا يعمل إذا كان Webhook مفعلاً. إذا كانت النتيجة فارغة، أرسل رسائل جديدة بعد إيقاف القارئ الآخر؛ لا تمسح تحديثات مشروع عامل عشوائياً. [توثيق getUpdates وحقول الرسالة](https://core.telegram.org/bots/api#getupdates).

## ٤. طريقة بديلة: رابط رسالة المجموعة

في مجموعة Supergroup خاصة، انسخ رابط رسالة. مثال توضيحي بأرقام افتراضية:

```text
https://t.me/c/1234567890/57
```

الجزء `1234567890` يحدد المجموعة، و`57` يحدد الرسالة. معرّف المجموعة بصيغة Bot API لهذا المثال هو:

```text
-1001234567890
```

هذا التحويل يخص رابط `t.me/c/...` لمجموعة Supergroup، وليس معرّف مستخدم أو رابط دعوة. إذا حصلت على `Chat ID` جاهز من البوت فلا تضف إليه `-100` مرة ثانية. [صيغ معرّفات Bot API](https://core.telegram.org/api/bots/ids).

قد يأتي رابط رسالة داخل موضوع بالشكل:

```text
https://t.me/c/1234567890/42/57
https://t.me/c/1234567890/57?thread=42
```

هنا `42` معرّف الموضوع و`57` معرّف الرسالة. **لا تعتبر آخر رقم في أي رابط معرّفاً للموضوع تلقائياً.** إذا لم يتضمن الرابط موضوعاً واضحاً، استعمل `message_thread_id` بالطريقة السابقة. الروابط العامة التي تحتوي اسم مستخدم بدلاً من `/c/` لا تعطي معرّف المجموعة الرقمي مباشرة. [صيغ روابط الرسائل الرسمية](https://core.telegram.org/api/links#message-links).

## ٥. ماذا أضع في شاشة إنشاء المشروع؟

| حقل التطبيق | القيمة التي تضعها |
|---|---|
| اسم المستشفى / المشروع | الاسم الذي تريد ظهوره في التطبيق |
| رمز البوت | الرمز الكامل من BotFather |
| معرّف المجموعة | `Chat ID` السالب للمجموعة المخصصة للمشروع |
| مجموعة المقيمين — اختياري | مجموعة أخرى للتقارير العامة؛ اتركها فارغة لاستخدام مجموعة المشروع |
| موضوع المقيمين — اختياري | رقم موضوع في مجموعة المقيمين؛ فارغ يعني دون موضوع محدد |
| موضوع التقارير | رقم موضوع التقارير داخل مجموعة المشروع عند عدم تحديد مجموعة للمقيمين |
| موضوع البيانات / CSV | رقم موضوع ملفات مزامنة المرضى |
| موضوع الأطباء | رقم موضوع سجل الأطباء |
| اسم المدير الأول | اسم الطبيب المسؤول عن الإدارة |
| معرّف تليجرام للمدير | `Sender user ID` لحساب الطبيب، ويكون موجباً |

أسماء المواضيع اختيارية؛ أرقامها هي التي تحدد الوجهة. المواضيع ليست إلزامية: **اترك الحقل فارغاً للإرسال إلى General، ولا تكتب `0` في حقل الموضوع.** إذا لم تستخدم المواضيع، اترك حقول المواضيع فارغة. معرّفات المواضيع تخص مجموعتها؛ لا تنقل رقم موضوع من مجموعة أخرى.

يمكنك تحديد مجموعة المقيمين أثناء الإنشاء أو لاحقاً من إعدادات المدير ← وجهات التقارير في Android، أو إدارة الفريق والمشروع ← وجهة تقارير المقيمين في الكمبيوتر. تبقى ملفات CSV وسجل الأطباء والفهرس المثبّت في مجموعة المشروع؛ التقارير العامة PDF والنصية تتبع وجهة المقيمين إن حُددت. بلا وجهة أو مواضيع إضافية يُرسل الجميع إلى المجموعة العامة. رموز التحقق تبقى في المحادثة الخاصة. يجب أن يكون البوت مديراً في المجموعة الإضافية، والموضوع إن حُدد تابعاً لمجموعة مفعّلة المواضيع. لا تُرسل رسالة تجريبية عند التحقق من الإعداد.

حفظ الوجهة لاحقاً يطبّقها على هذا الجهاز. صدّر ملف انضمام محمياً جديداً وأعد الاتصال به على الأجهزة الأخرى لنقل الإعداد؛ لا يتغير المشروع أو مفتاحه أو مرضاه، ويلزم تجديد معاينة التقرير بعد تغيير الوجهة. استخدام ملف قديم يعيد وجهته القديمة عند إعادة الاتصال؛ استخدم أحدث ملف موزع.

بعد التهيئة، يستخدم التطبيق رسالة مثبتة للوصول إلى حالة المشروع وسجلّه؛ أبقِ هذه الرسالة متاحة ولا تستبدلها برسالة عادية.

## ٦. التشفير وضم بقية الأجهزة

اختيار التشفير يولّد مفتاحاً عشوائياً مستقلاً عن رمز البوت؛ فك البيانات محلي، وPDF يبقى مقروءاً. صدّر `.srjoin.json` محمياً من إعدادات المدير: JSON بمحتوى مشفر يحمل الاتصال/المواضيع/المفتاح، دون إظهار الأسرار. أرسل كلمة المرور منفصلة واحفظهما للاستعادة. العضو يستورد ثم «التحقق والانضمام» دون إدخال معرّفات؛ الإدارة يحددها سجل الأطباء لا امتلاك الملف.

## ٧. استبدال رمز البوت

سجّل الدخول كمدير ← BotFather لإلغاء/تجديد رمز **البوت نفسه** ← الإعدادات/الأمان والخصوصية/إعادة الاتصال/استبدال الرمز كمدير ← تحقق واحفظ ← صدّر انضماماً جديداً لبقية الأجهزة (الإعدادات أو شاشة الدخول). الحفظ لا يلغي الرمز؛ BotFather يفعل. يبقى مفتاح البيانات والسجل المحلي؛ مشروع/مفتاح/مواضيع مختلفة مرفوضة.

## أخطاء شائعة

| المشكلة | ما الذي تراجعه؟ |
|---|---|
| الرمز غير صالح | انسخه كاملاً دون مسافات؛ لا تدخل `@username` بدلاً منه |
| المجموعة غير متاحة | تحقق من الرقم السالب وعضوية البوت وصلاحياته |
| لا تظهر تحديثات | أرسل رسالة جديدة، وأوقف قارئ التحديثات الآخر، وتحقق من عدم وجود Webhook |
| معرّف المدير غير صحيح | خذ رقم مرسل رسالة شخصية، لا رقم البوت أو المجموعة أو الهاتف |
| الإرسال إلى موضوع خاطئ | لا تخلط `message_id` مع `message_thread_id`؛ تحقق أن الموضوع من المجموعة نفسها |
| ملف الانضمام مرفوض | تحقق من عبارة المرور وأن الملف من المشروع نفسه |

رموز تليجرام ومعرّفاته تُدخل في إعدادات التطبيق، **وليست إعدادات بناء Android**؛ لا تضعها في `local.properties` أو `local.properties.example` أو هذا الدليل. جميع الأرقام في الأمثلة توضيحية وليست إعدادات مشروعك.
