# Temporary UI suggestions

Saved at the owner's request on 2026-10-19. The owner subsequently approved all six Android
items and five desktop items. Implemented; see [current state](../current-state.md#ward-interface-and-desktop-workflow-organization)
for behavior and verification limits. This note retains the original selections.

## Saved Android selections

1. **Cleaner ward header:** compact shift/status row followed by search and existing
   quick filters. Shorten «التصفية والعرض والترتيب» to «خيارات العرض», keeping
   active filters visible.
2. **More elegant patient cards:** emphasize the patient name, quieten team/admission
   metadata, align task counts, and use subtle neutral dividers while retaining
   clinical warning colors and access to full content.
3. **Focused display-options sheet:** separate «تصفية»، «تجميع»، and «ترتيب»;
   distinguish temporary display controls from sorting that changes saved order.
4. **Shorter report setup:** retain «أطباء المناوبة» first, then compact scope,
   format and destination summaries. Collapse appearance under «تخصيص التقرير»;
   preserve exact preview and explicit send confirmation.
5. **Settings organized by purpose:** compact category rows with current-value
   summaries, opening detailed controls inside each category to reduce scrolling.
6. **More discoverable rounds workflow:** expose the existing optional
   «حفظ والتالي» preference near rounds navigation; show patient position and
   a clear end-of-round state without adding a required acknowledgment workflow.

## Selected desktop improvements

- Slimmer right sidebar, with secondary tools in a separate settings window.
- Shorter ward toolbar with search, display options and Add together.
- Quieter patient cards with a compact secondary-action menu.
- One report workspace for scope, destination, format and appearance.
- Stable patient widgets during search, preserving expansion and filter/reset scroll.

The desktop split-pane proposal was not selected. Original suggestions were based
on source inspection. Completed behavior and verification are recorded in current
state; these are not unfinished roadmap items.
