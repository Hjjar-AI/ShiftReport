## Data and synchronization

Arabic offline-first Android/desktop handover: Compose/Hilt with encrypted Room; Python/CustomTkinter with encrypted SQLite. Current formats only: protected join, registry/index and single-ward CSV8/24-column bundle, including ordered dated lab groups. Existing fields/rows remain. Android database8 adds lab-group JSON with a row-preserving7→8 migration; database7 relaxed unique ward-date and historical doctor-name indexes; IDs remain identity and Telegram accounts stay unique.

Manual Fetch reads the current Telegram pin and completely replaces local patients/doctors, including pending edits. It validates the final pair and saves one encrypted pre-Fetch Undo, restoring data and selection **locally only**. Doctor-only Fetch validates retained clinical references. No merge or older-message gate. Last successful index write wins; Telegram supplies no atomic multi-writer guarantee. Publication requires review, final confirmation and live authority checks.

One continuous ward; explicit IDs and stored dates survive. 08:30 changes displayed/report day only. No rollover, dated browsing or deadline. Clinical saves use last-save-wins with existence/deletion/ward/assignment checks. Tasks are explicit text/done records; current hidden metadata remains.

## Security and recovery

Project creation presents numbered connection/admin/protection sections, explains a single group versus optional topics within it, and collapses optional residents routing with retained-value notices. Inline numeric-ID help and detailed private message-link examples guide manual configuration. Join accepts file selection and password in either order, with the file button above the password. Both are required for explicit unlock and project review before joining; file URI/password stay in ViewModel memory and password clears after unlock. Join uses password-protected `.srjoin.json`. Encryption is chosen at creation; reconnect validates project/key/topics and preserves records. Missing keys preserve files for recovery. PDFs are readable; secrets stay out of logs, saved UI and exports.

Telegram login uses a private six-digit code, memory-only salted hash, five-minute expiry and five attempts; no shared update-queue polling. Offline PIN entry requires device enrollment for the current linked identity/hash. Live admin/identity and privileged-account guards remain below UI. PIN cooldown is 5/15/60 minutes; default auto-lock is five minutes.

## Clinical write safety

Repeatable lab groups have optional titles and calendar-selected dates, multiline results, compact up/down/delete icons beside each group heading (Arabic TalkBack/tooltips and48dp targets, with deletion confirmation), and preserved unfinished entries in encrypted drafts. Existing labs remain one untitled, undated group. Android and desktop editors share the grouped wire representation; cards/search/text/classic reports retain readable headings/dates/results. Drafts retain all form/unfinished task text. Unreadable drafts block autosave until recovery. Save and draft deletion commit together; late autosaves cannot recreate discarded drafts. Assignment roles are checked transactionally. Fetch/Undo preserve assignment dates. Backup restore never publishes; verified exported files survive later bookkeeping failure/cancellation. Deleted patients remain recoverable for at least seven days.
