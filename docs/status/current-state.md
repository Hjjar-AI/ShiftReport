## Synchronization and publication

Retrieve → local edit → review → complete-snapshot publish; last successful pinned write wins. No automatic sync, field merge, atomic multi-writer guarantee or required backend. Timestamps record events, not current freshness. Preserve revisions/identity/assignment/registry-pointer/uncertain-delivery guards; unrelated registry edits need not block patient publication.

Android «مركز المزامنة» reuses the Data destination: four collapsible cards for patients, doctors, files/import/export and encrypted backups. One section opens at a time (patients initially); selection survives recreation, and transfer errors open the relevant section. Collapsed patient/doctor headers show pending status and last contact. Connectivity, recovery actions and last-operation feedback stay above the cards, visible when sections are collapsed. The center omits the redundant section-index strip; standalone settings workspaces retain their existing layout. A direct drawer row, settings link and patient/dashboard status details open it; report-review shortcuts remain. It observes connectivity, device-wide pending flags and last-contact times without claiming remote freshness. Patient fetch asks for confirmation; publication retains the existing reviewed snapshot/final confirmation. Transfer issues persist with doctor-registry or patient-publication recovery and an explicit retry; sync retry state is independent of file-export feedback. Doctor mutation/publication remains admin-only in the existing registry screen, with non-admin guidance. CSV/import/backup keep existing owners and busy guards; no automatic transfer/backend/schema change. Latest center is source-only: resource/diff inspection, no compilation/tests/device/live operation.

`SyncService`/`DoctorSyncCoordinator` share singleton `RemoteSyncStateStore` mutex; tokens/journals/artifacts retain one owner. Snapshot equality differs from device-wide pending state. Fetch Undo/history/rollover stay separate. Permanent-superadmin empty-start retains accounts/config/key/audit/receipts/Telegram history; other devices retrieve replacement.

Doctor management exposes Publish, Fetch and CSV Import directly; team/export remain secondary. Pending changes have a persistent review-and-publish action; Add/Edit and deletion errors stay visible in their forms/review, and ordinary registry errors remain above the list. Patient-download failures show persistent typed recovery: open the doctor registry or review patient publication, then explicitly retry the original download. Report registry blocks explain the same steps and offer a report reload after publication; no automatic upload, discard or resend. CSV import retains reviewed local commit followed by complete-registry publication. Shift-doctor selection and registry/import/team reviews use full-screen inset-aware layouts with fixed actions; selection search/count stay above the scrolling list. Explicit doctor deletion removes that doctor from the current shift roster in the same authorized Room transaction, increments the shift revision, marks patient/doctor changes pending and audits the roster change. Clinical/unfinished-task/team/admin guards still apply and roll everything back on rejection; historical rosters and remote/import deletion protections remain intact. Empty resulting current rosters require a new selection before reporting. Offline production compilation passed; device behavior remains unverified.
